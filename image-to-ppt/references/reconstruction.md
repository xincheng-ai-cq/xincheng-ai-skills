# 重建与结构检查

## 执行环境

这是工作流 skill，不是无需人工判断的全自动 OCR 转换器。先读取图片，再建立原生 PPT 对象；不要把 OCR 输出直接塞进固定模板。

环境已有 presentations skill 时，使用它规定的作者工具、运行时定位、字体检查、导出和逐页渲染流程。当该 skill 使用 `@oai/artifact-tool` 时，读取其 `references/implementation.md`、`artifact_tool_docs/API_QUICK_START.md` 和 `references/finalization.md` 后再编写 JavaScript。工具路径通过可用的 `load_workspace_dependencies` 获取，skill 路径通过可用 skill 列表获取。其他环境遵循其中实际可用的作者工具和运行时。

图片是用户指定的视觉参考，可编辑重建需要的原生形状属于任务本身。忠实保留用户要求的形状与布局，不以通用美化规则替换它们。没有配套作者工具时可使用环境已有且支持所需原生对象的演示文稿工具；如当前环境无法生成或渲染 PPTX，说明具体限制，不交付整页图片来冒充可编辑版本。

使用支持 PPTX 的 live session 时，可以在 session 内重建和渲染；导出文件后仍检查实际原生对象。不要为了本 skill 修改全局软件配置或安装未知来源的 OCR 程序。

## 混合 PPT 与公共素材

### 分类与保留基准

记录原 PPT 的页序、对象类型、字体、格式、关联资源和逐页渲染，列出整页图片版及所有非目标页。宽高均接近整页、缺少有效原生正文的图片是分类线索，不是绝对判据：95% 覆盖率不能独自证明该页需要转换；可编辑页也可能有整页干净底图，图片版也可能另有原生页码或标志。比较图片内容与其他页共享背景的摘要值，再实际查看是否包含固化的文字和版式骨架。拿不准的页先问，其他已明确的页继续处理。

默认只替换整页图片版。原生文本、表格、图表、形状及局部混合页保留，用户明确指定局部重建时才处理该区域。原文件不修改，最终交回保持全部页数和页序的完整副本。

### 原位替换与页头复制

优先使用能保留原页面及关联部件的编辑流程。普通作者工具整体导入再导出可能改变未修改页，不以“没有主动编辑”证明它们未变。必要时在私有构建文件中生成目标页的重建内容，再回写源 PPT 副本中的对应页面部件；只修改目标页及其需要新增的资源。保持非目标页的原 XML、字体、布局、母版、主题、图片、图表、备注和关系。维护幻灯片顺序、关系 ID、资源路径和内容类型，不能仅替换一个 slide XML 而漏掉资源。

复制原生页头时保留组合及各子对象的实际位置、字号、颜色、字体和富文本 runs，只修改对应的编号和标题文字。复制 XML 或对象时为目标页分配不重复的 `cNvPr id`，重映射图片、超链接等关系；保留或正确映射源布局和主题，防止主题字体或颜色发生变化。直接复制的原生图标保留原对象形式。

若标题需要变宽，先检查可用空间与用户规定的样式。组合使用 `off/ext` 和 `chOff/chExt` 映射坐标；只改一侧的宽度可能缩放整个页头。调整时同时处理文本框与组合坐标，使其他子对象的实际位置和大小不变，再渲染核对；空间不够或样式不能确定时向用户说明具体冲突。原页没有横线、阴影或装饰就不补加。

保留目标页原有的非图片对象，如标志、页码和已有页头，按原层叠关系复用；避免与新复制的同一元素重叠。共享母版或布局若需为目标页调整，建立目标页专用副本，不改变其他页共享的部件。无法保持非目标页时换用能保留原部件的流程；仍受限时说明具体对象和差异，不把完整重做当成无变化交付。

### 共用底图与资源清理

按公共风格分组记录底图资源、标题与表头样式、固定装饰的位置和 PNG 图标素材。相同素材复用同一文件或同一资源；如果源 deck 已有适用的母版或布局，直接复用。不要为了风格统一重新生成不同页面自己的照片或内容图。

干净底图只含背景纹理和背景画面；标题栏、色块、卡片、页签、编号底块、箭头、分隔线和独立内容图片应从背景分离。统计同一模板组的底图资源与摘要，确认确实复用同一份，不把全部版式不同的页面强制共用一张。已有背景仅为填充时复用其定义。

删掉旧整页图形后，先检查目标 slide 中是否还有对象使用其 `rId`，再删除确实无人使用的图片关系。然后检查整个包的关系图，包括隐藏页、母版、布局、备注和其他部件，只有全包已无引用的旧图片才可移除。同步更新相应内容类型声明；不要仅按图片尺寸、文件名或重复摘要删除。保留其他页仍使用的图片和关系。

清理完成后重新打开文件、检查全部内部关系并重新渲染全册。不能以删除一个 shape 就认为大图片已从 ZIP 包消失，也不能以压缩后体积变小代替内容和关系检查。

图标生成使用可用的图像生成能力（环境有 imagegen skill 时按其说明执行），匹配源图并输出 PNG。普通几何形状和连接线仍由 PPT 作者工具生成。图标文件应检查 PNG 格式与所需透明度；图标文字标签单独保留为原生文本。

## PDF 对象提取与干净底图

先检查页尺寸、文字层、图片位置和矢量路径，再将原页渲染为对照图。整页图片优先提取原始嵌入位图，保留原分辨率；不要用低分辨率的整页重渲染代替现有清晰素材。

有原生内容时，提取文字、字符或文本段的边界框、基线、字号、颜色和对象矩阵；拆出独立图片，简单矢量路径转成原生形状。复杂插画可保留为独立图片，图表精确数据只从真实数据或可辨认标签获取。字体子集名称可帮助判断原稿，但新文字仍遵循默认微软雅黑及复制页头例外。

在 PDF 的私有副本中分离前景文字、版式骨架和独立图片后，渲染剩余背景，或直接提取已有干净背景资源。对含混合内容的 Form XObject、裁切和透明组逐层检查，不能仅移除顶层文字就认为背景已干净。原 PDF 不修改，不能用白色遮挡块覆盖文字后把它当作干净背景。

对象分离使用环境已有且支持相关能力的 PDF 工具。可用 PDFium 等对象 API 时按当前版本的接口处理；没有对象删除 API 时，可提取背景资源或重建公共背景。需要去字、补底、抠图或其他图像编辑时，遵循环境图像工具及 imagegen skill 的约束，不照搬其他环境的算法或模型下载命令。复杂背景只制作一份并检查后同组复用。

提取图片时正确处理图像变换、裁切、旋转、`SMask`、透明度及 `/Matte` 预混信息。简单附加 Alpha 可能造成黑边，按 PDF 的原有解码规则处理并与原页核对；这属于源素材解码，不改变图像内容。透明 PNG 在有对比色的预览背景下检查边缘、内部空洞和细小部件，再放回页面比对，不遗漏地图小岛、人物细节或 Logo 边缘。

## 坐标和文本

设原图有效区域宽高为 `Wi, Hi`，输出画布为 `Ws, Hs`，先扣除有效区域的原点，再换算坐标：`x' = x * Ws / Wi`，`y' = y * Hs / Hi`，宽高同理。保留比例时使用统一缩放并加上留白偏移。

字体大小必须遵循作者工具的实际单位，不把图片像素直接当作磅值。中文字体替代会改变字宽和换行，先调整字间距、段落间距和文本框边界，再与原图对照。若表格或图表的关键数值看不清，不能通过视觉高度估算后当作真实数据。

使用放大图、网格或局部裁切图测量时记录缩放系数及裁切原点，读数换回原页的绝对坐标，避免把局部图的 `(0,0)` 当作整页原点。EMU、像素和磅按实际输出画布及工具单位换算，不固定套用其他项目的 16:9 尺寸或字体估算公式。

颜色和几何以本次原稿为准：纯色色块用内部稳定区域取色，文字用核心墨迹取色，渐变检查方向和多个停止点；图像边界或连通区域检测只作辅助，结果仍需渲染对照。不硬编码其他项目的青绿色阈值、面板透明度、阴影或圆角半径，不自动给原稿没有的对象添加主题阴影。

字体检查覆盖正文、表格及实际使用的文字脚本，特别是东亚中文字体字段；需要时同时核对 `a:latin`、`a:ea` 和 `a:cs` 的实际继承结果，不能仅看到 latin 写着微软雅黑就判定中文也使用该字体。复制页头保留原来的字体字段。核实渲染所用字体实际可用，不用全局字体别名把其他字体的预览当作微软雅黑实测，也不承诺未经实现和验证的字体嵌入。

## 原生形状渐变

对原稿中每个带渐变的版式形状，记录渐变类型、方向或中心、色标的颜色与位置、各色标透明度及形状边界。用作者工具提供的原生 PPT 渐变填充绑定到对应形状，保持线性或路径渐变的实际效果；原稿简单线性渐变可使用两端色标，多色或透明渐隐应保留相应中间色标。颜色、角度和位置均以本次原稿为准。

导出后检查目标形状实际生效的渐变定义，例如其 `a:gradFill` 及渐变停止点、方向、透明度，不能只统计整个主题文件里有没有渐变。渐变图片、图片填充、纯色或多块纯色色带都不能证明完成了原生渐变重建。复制页头时保留原渐变及其依赖的主题颜色，避免主题映射后变色。

逐页对照渐变的方向、明暗、颜色过渡和边缘透明度。在私有编辑副本上修改一个真实渐变色标的颜色或位置，保存并重新打开，确认改变保存在原生渐变中；交付原来匹配原稿的成品。软件不能表达某种原稿渐变时，说明具体限制并继续寻找可用原生方案，不默默替换为位图或纯色。

## 并排比较与编辑副本

原稿和成品用同一渲染环境、画布尺寸和缩放并排比较；必要时加叠图或像素差图，指标只作定位辅助。未转换页优先同时核对原 XML 和关联资源，再比较文字、字体、格式、几何与渲染结果。不能把某次案例的平均像素差阈值当作通用通过标准，发现差异时查明是内容变化、资源变化、字体替代还是渲染波动。

在最终候选成品的私有副本上，用可实际编辑并保存 PPTX 的工具修改本次重建对象，优先 PowerPoint 或用户指定的软件。至少改一段文本、移动一个图标或独立图片、换一个原生形状的填充色，有表格时修改一个单元格；包含合并和富文本时一并确认这些结构仍正常。有渐变形状时还要修改其原生渐变色标，按上面的渐变规则验证。不存在的对象类型记为不适用，不为测试而新增对象。

保存编辑副本并重新打开，核对修改后的文字、位置、颜色和单元格值确实持久化，再渲染确认其他内容没有被意外修改。测试副本留在私有目录，交付原成品，不把测试文字或颜色带给用户。只做了包结构或预览检查时明确界限，不宣称已在 PowerPoint 或其他实际未使用的软件中验证编辑。

## audit_pptx.py

脚本使用 Python 标准库只读检查 `.pptx` 中的 XML，列出每页原生文本框、原生非文本形状、表格、图表、图片和分组。它不进行 OCR、渲染或转换。

基本用法（`<python>` 替换为实际可用的 Python 3 解释器，`<skill-dir>` 替换为实际目录；有空格的路径按所用 shell 正确引用）：

```text
<python> <skill-dir>/scripts/audit_pptx.py output.pptx --output work/editability.json
<python> <skill-dir>/scripts/audit_pptx.py output.pptx --expect work/expected.json --output work/editability.json
```

提供期望清单后，声明的原生对象或关键文字缺失会返回退出码 1；无法读取或清单格式错误返回 2；声明条件通过返回 0。未提供清单时返回的是结构检查结果，不是“全部可编辑”的认证。

下面只展示清单格式；页数、对象数量和文字必须根据本次输入填写，不得沿用示例数字：

```json
{
  "slide_count": 2,
  "slides": [
    {
      "number": 1,
      "min_textboxes": 3,
      "min_native_shapes": 2,
      "min_tables": 1,
      "min_charts": 0,
      "required_text": ["主要业绩", "2026"]
    },
    {
      "number": 2,
      "min_textboxes": 2,
      "min_charts": 1,
      "require_chart_workbooks": true,
      "required_text": ["单位：万元"]
    }
  ]
}
```

`min_native_shapes` 统计有原生几何定义的非文本形状及连接线。`required_text` 检查文本框与表格文字，忽略 Unicode 空白差异；不会 OCR 图片中的文字。图表数据和标签应另外对照来源核对。

`require_chart_workbooks` 仅在必须编辑图表数据时设置。脚本检查图表的外部数据关系是否指向包内的工作簿部件，配套作者工具的校验器负责进一步验证工作簿内容与图表数据。

近乎覆盖整页的图片会触发人工检查提示：可能是正常的无文字背景，也可能是截图底图。不要仅凭提示自动删除图片；对照源图和对象清单，确认不存在被固化的必要内容或叠加重影。

## 校验边界

对象数量不代表内容覆盖率。即便原生文本框很多，也可能遗漏了主标题、用矩形拼成了假表格，或只是叠在原截图上。结合输入清单、导出结构、重新渲染的每页预览一起验收；未通过视觉核对的结构报告不能支持版式已还原的结论。
